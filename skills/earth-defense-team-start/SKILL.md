# 地球防衛隊開案

將小隊的合作方式帶入目前專案，不把私人角色資料複製進客戶程式庫。角色以小隊儲存庫文件為準，不在本 Skill 重複定義。

## 找到並核對小隊來源
- 使用使用者指定的小隊 checkout；其次可使用環境變數 EARTH_DEFENSE_TEAM_HOME。若本 Skill 位於小隊儲存庫的 skills 目錄，可由其上層找到根目錄。找不到時只詢問小隊資料夾位置，不遍歷整台電腦。
- 預期來源 https://github.com/Rayi0406TW/Earth-Defense-Team.git，基線分支 codex/team-baseline。使用者指定其他分支時尊重指定。核對 origin、目前分支與工作樹，記下實際提交。
- 在一般工具與權限允許下 fetch 預期分支核對遠端。僅在工作樹乾淨、目前分支正確且可快進時同步。若有未提交變更、分歧或分支不同，保留原狀並說明，不能 reset、stash、覆蓋或自動切分支。
- 網路或登入不可用時明確標示未核對最新；有本機文件可依使用者允許繼續，不能聲稱已同步。缺少來源時可在使用者指定、且與客戶專案分開的空資料夾 clone，不能將小隊文件混入目前客戶庫。不得讀取或複製憑證。

## 讀取與接手
- 讀小隊根目錄 README.md、WORKING-AGREEMENT.md、MEMBERS.md，以及使用者指定角色文件；未指定時讀 members/TRACY.md，以 Tracy 為主要窗口。
- 成員由名冊決定，不把人數限制為三位；只按任務需要讀其他角色。名稱不是工具權限，也不代表已有相對應執行中任務。
- 再讀目前工作專案適用的 AGENTS.md、README、既有規格/交接與 Git 狀態。小隊資料不取代專案決策，舊案授權不自動延伸到新案。
- 有目標時整理完成條件、現有進度與下一步，接著推進已授權工作；缺少目標時僅詢問本次要達成什麼。不要為每個開案增加多餘批准關卡。
- 需要實作或複驗才安排相應成員；遵循當前環境對任務建立與委派的規則。只有成功建立或傳送後才能說已分派，不因載入名冊就宣稱小隊已在執行。

## 開案回報
簡短回報實際讀到的角色/合作規則版本、同步狀態、本案目標、準備使用的分工、下一步及必要阻塞。區分「建議分工」與「已派工」。不輸出機密或完整私人偏好到其他專案。不要自行 commit/push、寄送、建立遠端或部署；依該案明確授權執行。

本 Skill 是開案流程，不是完整對話遷移或自動永久記憶。若遠端 Skill 本身已有更新但安裝副本不同，提示同步安裝版本，不默默改寫全域設定。
